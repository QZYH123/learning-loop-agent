# 29 — 资料检索质量与引用跳转

**Type:** task

**Status:** resolved

**Source:** 竞争力判断：资料严格模式的价值完全取决于召回与可核查。现状 `SourceLibrary.retrieve` 是纯词频计数，中文按**单字**切分（`_query_terms` 的 `[\u4e00-\u9fff]` 单字正则），高频字噪声大；引用芯片（`.cite`）只能悬停看摘录，不能跳回资料原文（spec 11「回答带有可查看的来源位置」只兑现了一半）。

## 范围

做：检索打分升级（无向量库）、引用点击跳转资料锚点、固定召回评估样例。
不做：向量数据库、Embedding 服务、重排模型、检索缓存改造。spec 原则不变：是否引入向量库由本票建立的召回数据决定，本票先把词法检索做对。

## 设计规定

### 检索打分（`backend/app/sources.py`）

- `_query_terms`：中文改为**相邻双字 bigram**（「拥塞控制」→「拥塞、塞控、控制」），保留现有英文/数字词切分；查询不足 2 个汉字时退回单字。锚点文本按同规则切分。
- 打分改为 BM25：`k1=1.5`，`b=0.75`，IDF 在**本次所选 version_ids 的锚点集合**内计算（文档 = 锚点）。实现为纯函数放在 `sources.py` 内，不引新依赖。
- 加权：`location.label` 或标题类 location 字段命中查询词的锚点，得分乘 2（heading 命中比正文命中更可信）。
- 结果去重：`_anchor_text` 前 200 字符相同的锚点只保留得分最高的一个。
- 保持不变：`retrieve` 的函数签名、priority_version_ids 优先级语义、图片锚点兜底逻辑、`retrieve` stage 观测记录。

### 引用跳转（前端 + 少量后端）

- `chat.js` 与 `solution.js` 的 `.cite` 芯片从 `span` 改为 `button`，`data-action="open-citation"`，携带 `data-source-id`、`data-version-id`、`data-anchor-id`（citation 对象已有这三个字段；若个别渲染处只有 citation_id，先经 `GET` citation 换取，不改 citation 存储）。
- `app.js` 新增 `openCitation`：切到资料区 → 选中对应资料并显示对应版本详情 → 滚动到该锚点并高亮约 2 秒。资料详情渲染需给每个锚点块加 `id="anchor-{anchor_id}"`（或 data 属性）作为滚动目标。
- 资料版本不可用（HTTP 410）时 toast「资料已不可用」，不跳转、不报错栈。
- 视觉：高亮用现有语义软底色一闪即隐（0.15–0.2s 过渡），不引入新颜色变量；`.cite` 变按钮后保持现有胶囊外观，加 hover 底色即可。

### 召回评估样例

- 用现有 evaluation-suites / 观测后端建一组固定样例：≥10 条「查询 + 期望命中的资料与锚点位置」，覆盖中文短语、英文术语、表格内容、公式名各至少 2 条；固定资料文件放 `backend/tests/fixtures/`。
- pytest 断言：top-5 召回命中率 ≥ 基线（先跑旧实现记下基线，新实现不得低于且应高于它；两个数字都写进测试注释）。此后检索改动必须过这组样例。

## 验收标准

1. 双字词查询（如「拥塞控制」）不再被无关高频单字锚点挤掉（评估样例断言）。
2. 聊天引用芯片和题目出处芯片点击后落到资料区对应锚点位置并高亮。
3. 严格模式「未覆盖」语义不变（现有测试不回归）。
4. 全量 pytest 通过，评估样例全绿并记录基线数字。

## Answer

偏离：AI 文档 citation 只切到资料区文档 tab，文档详情没有锚点 id，不滚动高亮。依据标签（「依据资料」等）仍是 span，不是可跳转引用。
