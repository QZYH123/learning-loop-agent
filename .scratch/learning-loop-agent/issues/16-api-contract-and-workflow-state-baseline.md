# 16 — API 契约和工作流状态基线

**What to build:** 先定义多会话、资料上下文、模型发现、AI 资料文档和作答状态的静态 HTTP 契约，并收敛当前已发现的前端契约差异。此 Issue 只修改 `docs/api/` 和契约测试，不实现业务后端或前端。

**Blocked by:** None

**Status:** ready-for-agent

## Contract

- [ ] 定义科目内多学习会话的列表、创建、读取、更新、删除和当前会话切换接口
- [ ] 定义会话资料范围、固定 `source_version_id`、显式加入/移除/更新版本的请求和响应
- [ ] 定义消息级资料上下文快照，包含实际资料版本、模型、依据模式、选区和附件引用
- [ ] 定义 `@资料` 的重点检索语义，以及显式“仅使用指定资料”的请求字段
- [ ] 定义消息级临时附件的上传、引用、生命周期和 Vision 能力错误
- [ ] 定义 OpenAI-compatible `/models`、Ollama `/api/tags` 的发现请求、规范化响应和错误结构
- [ ] 定义模型配置列表、当前模型选择、手动测试和手动模型名兜底
- [ ] 定义 AI 生成资料文档、文档版本和修改提案接口
- [ ] 将作答状态拆分为用户完成状态和批改状态，并定义完成、恢复、提交批改的接口
- [ ] 增加资料版本锚点列表接口，避免前端读取不存在的摘要字段
- [ ] 修正 Chat 内容块、资料字段、选区 `document_kind` 等现有契约不一致
- [ ] 为所有新增接口补充错误码、状态码、示例和 `x-tickets` 追踪

## Verification

- [ ] OpenAPI 文档和 Schema 通过契约校验
- [ ] 契约测试覆盖成功响应、校验失败、资源冲突、资料失效和能力不支持
- [ ] 契约中不包含未实现的原生 Anthropic 或 Gemini 协议适配器
- [ ] 后续实现 Issue 不得绕过本 Issue 直接新增未定义字段或接口
