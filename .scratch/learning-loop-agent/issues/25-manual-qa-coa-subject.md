## 问题

### P1 — 全屏资料/组卷区有大块无操作空白

**复现：** 宽屏下资料、组卷右侧空状态把装饰图标和标题垂直居中铺满整栏；有内容时正文又被限制在约 860px，右侧剩一大片空纸。作答区当时没有试卷，未核实。

**对照：** 规范禁止用装饰填空白；每个空状态两行加一个动作即可。

**期望：** 空状态靠上、紧凑；有内容时任务区吃满可用宽度，不再用稿纸涂鸦撑版面。

### P1 — `/改卷` 在草稿上提示「请先选择一份试卷」

**复现：** 组卷区已有草稿时发送 `/改卷 把第一题改简单一点`，命令仍按已发布试卷处理，回「请先选择一份试卷」，并为此建一条失败会话。

**期望：** 当前对象是草稿时，`/改卷` 走同一套修改预览（生成差异，再应用/放弃）。没有草稿也没有试卷时禁用命令，且不建会话。

### P1 — 开始组题后草稿区长时间空白

**复现：** 确认蓝图 → 点「开始组题」。接口已创建 `generating` 草稿，导航栏也出现忙碌计数，但草稿页立刻变成「还没有草稿 / 用对话组卷」，整段生成过程（约十几秒到更久）看不到逐题进度。

**对照：** 规范要求题目逐个出现并显示状态。前端 `generateDraft()` 先切到草稿 tab，却等 `pollOperation` 全部结束后才 `listDrafts`，`watchDraft()` 也在轮询结束后才挂上。

**期望：** 一点「开始组题」就出现草稿和各题状态（生成中 / 失败 / 已生成），并随题目落地刷新。

### P1 — 题目结构校验失败时把内部字段名当题干

**复现：** 本轮草稿：

| 题 | 状态 | 用户看到的正文 |
| --- | --- | --- |
| 1 | 失败 | 无法连接模型服务，请检查 Base URL 和网络设置 |
| 2 | 待复查 | `content blocks must be a string or list` |
| 4 | 待复查 | `'blanks'` |
| 5 | 待复查 | `'scoring_points'` |

**问题：** 「待复查」题没有重试按钮（重试只挂在 `failed` 上）。用户无法从界面修 2/4/5 题。错误文案是实现细节，不是学习者能理解的说明。

**期望：** 结构错误用中文说明缺什么；待复查和失败都提供重试；不要展示字段名或英文校验句。

### P1 — 发布按钮在草稿未就绪时仍可点

**复现：** 5 题里 1 失败、3 待复查时，「发布试卷」仍是主按钮。点击后 `POST /api/exam-drafts/{id}/publish` 返回 409：

```json
{"ok":false,"error":{"code":"QUESTION_EVIDENCE_INCOMPLETE","message":"草稿包含失败或待核查题目，请明确确认"}}
```

右下角 toast 才提示。按钮未 disabled，也没有二次确认「仍要发布」。

**期望：** 有失败/待复查题时禁用发布，或明确「仍要发布」确认；错误不要只靠 toast。

### P1 — 同名再上传变成第二份资料，而不是新版本

**复现：** 已有 `coa-notes.md`（22:05）后再传同一文件，列表多出另一张 `coa-notes.md`（22:18）。两份 `version_count` 都是 1。资料详情没有版本列表。

**对照：** 资料变化应产生新版本，旧引用可复查。会话资料抽屉里两份同名无法区分。

**期望：** 同名或同来源更新落到同一资料的新版本；卡片显示版本号；详情可看历史版本。

### P1 — 学习区资料抽屉盖住会话列表和对话

**复现：** 学习区点资料图标后，「会话资料」菜单变成大块白底，从顶栏拉到输入框上方，盖住左侧会话列表和中间消息。条目只有文件名，没有状态/版本。固定后仅靠右侧勾选标记，列表极宽、内容极疏。

**对照：** 资料应用抽屉或弹层，且不能挡住当前对话和会话位置。

**期望：** 下拉贴在资料按钮附近，宽度随内容，不遮会话栏；同名资料可区分。

### P2 — 空状态与对象名称不符

**复现：** 组卷「蓝图」tab 空状态标题是「还没有试卷」，不是「还没有蓝图」。草稿 tab 是「还没有草稿」，试卷 tab 是「还没有试卷」。

**期望：** 蓝图空状态说蓝图。

### P2 — 依据菜单不贴着盾牌按钮

**复现：** 点输入框旁「依据」后，菜单出现在对话区右下，空白状态下远离输入框；有消息时压在发送按钮附近。实现是写死的 `bottom: 58px; right: 54px`。

**期望：** 菜单锚定依据按钮。

### P2 — 科目菜单长名称折行

**复现：** 「计算机组成原理与体系结构」在下拉里被拆成「……体」+ 单独一行「构」。导航芯片用省略号，菜单没有。

**期望：** 菜单项完整可读，或统一省略且 tooltip 给全名。

### P2 — 切换科目会带走输入草稿

**复现：** 在测试科目输入「草稿测试：什么是冯诺依曼结构？」后切到「计算机网络」，组卷输入框仍是这句话。`composerText` 是全局 UI 状态，不跟科目走。

**对照：** 不同科目的本地状态应隔离。

**期望：** 草稿按科目保存，或切科目时清空。

### P2 — 无试卷仍可点 `/改卷`，并生成一条失败会话

**复现：** 空科目输入 `/`，`/改卷`、`/改文档` 均可点。发送 `/改卷 把第一题改简单一点` 后新建会话，标题就是这句命令，AI 回「/改卷失败：请先选择一份试卷」。

**期望：** 没有当前试卷/文档时禁用对应命令，或拦截并不创建会话。

### P2 — 新建科目空名称无反馈

**复现：** 「新建科目」对话框不填名称点「创建」，对话框留着，无校验、无 toast。

**期望：** 提示需要名称。

### P2 — 资料卡片文件名被裁切

**复现：** `coa-pipeline.png` 卡片显示成 `coa-pipeline.p`。横向卡片区还出现粗滚动条。

**期望：** 文件名完整或省略号 + tooltip。

### P2 — 资料正文位置标签和标题重复

**复现：** `coa-notes.md` 第一节标签是「计算机组成原理笔记」，下面又是同名一级标题。DOCX 每个锚点标签都是「CPU datapath」。

**期望：** 位置标签用「第 1 节 / 原文位置」，不要和正文标题重复一整行。

### P2 — 苏格拉底风格仍直接给完整答案

**复现：** 会话风格已是「苏格拉底」，在资料严格模式下问「冯·诺依曼结构由哪几部分组成？」。回答直接列出五部分，没有反问或引导。

**说明：** 可能是提示未生效，也可能是模型没遵守。需要确认风格是否写入当次请求。

### P3 — 来源引用过宽、芯片过长

**复现：** 只问冯·诺依曼组成，引用却带上流水线、存储器层次和整篇笔记。芯片文案是 `coa-notes.md · 计算机组成原理笔记 / 冯·诺依曼结构`，一行排不下。

**期望：** 引用对准被用到的原文位置；芯片缩短为资料名 + 短位置。

### P3 — 蓝图题型/题量/分值不能改

**复现：** 自然语言蓝图解析成功，考点芯片可删。单选/判断/填空/简答的题量、难度、分值只读。规范要求蓝图可编辑。

**期望：** 确认前能改题型计划，冲突时提示。

### P3 — 草稿不能手改题目

**复现：** 已生成的判断题只能看，不能改题干、答案、分值或顺序。失败题只能等重试。规范要求可直接编辑题目。

**期望：** 可编辑题干/选项/分值/顺序，并支持局部重试。

### P3 — 删除用浏览器原生 confirm，没有影响范围

**复现：** 删除资料/会话走 `window.confirm('删除这份资料？')` / `删除该会话？`。科目删除用应用内对话框。规范要求删除时看到影响范围。

**期望：** 统一确认框，并列出会受影响的会话、试卷或引用。

### P3 — favicon 404

**复现：** 打开应用控制台：`GET /favicon.ico` 404。除此之外本次走查未见未捕获 JS 异常。

### P3 — 历史会话把模型原始 JSON 当错误正文

**说明：** 未在测试科目复现（按要求不测模型配置），但打开已有科目「计算机网络」时，失败消息里有 HTTP 401/403 原文，并带 `sk-12345*7890` 一类脱敏不彻底的片段。

**期望：** 只显示短中文错误，不展示供应商 JSON 或密钥残段。
