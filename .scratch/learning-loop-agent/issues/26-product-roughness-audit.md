# 26 — 功能完成度、交互与冗杂设计调研

**Type:** research

**Status:** needs-triage

**Source:** 2026-08-20 对照 `CONTEXT.md`、`docs/frontend-workspaces.md`、spec 用户故事、OpenAPI 契约、现有 Issue 注释和当前前后端实现。本轮不改项目代码。已核对 23/24/25 后续合入，不把已修项再记一遍。

**Copy and layout source of truth:** `docs/frontend-workspaces.md`。领域词以 `CONTEXT.md` 为准。

## 范围与方法

从三条线看「实现已经接上、但作为完整产品仍粗糙」的模块：

1. **功能完成度**：spec / 契约已承诺，后端或前端缺一截，学习者走不完闭环。
2. **交互体验**：功能在，但状态、对象、默认值让人费解或容易做错。
3. **冗杂设计**：双轨接口、废弃路径、重复入口、界面堆叠，维护成本和认知成本都偏高。

本票是调研结论和拆票建议，不是一张可直接开工的实现清单。优先项建议拆成独立 Issue 后再标 `ready-for-agent`。

## 不要重做

下列已在近期合入或由 23/24/25 收口，不要当作新缺口：

- 组卷空状态、`/改卷` 打草稿、组题过程可见、待复查可重试、未完成草稿禁用发布
- 同名资料新版本、资料抽屉、依据菜单锚定、输入草稿按科目隔离、应用内删除确认
- 蓝图考点芯片可删、待确认蓝图可改题量/分值
- 草稿/试卷展示解析、考点、出处；作答练习模式客观题即时对错，主观题「本题反馈」
- 蓝图/试卷选中卡重命名、作答经过时间、对话风格四字对齐
- `/组卷` 可无参数、默认蓝图、导航栏模型/主题靠右、API 格式应用内菜单

Issue 22（文案与键盘）、14（导出前端）、15（观测前端）、20（AI 文档版本）的勾选框大多仍空，但其中一部分界面已经存在。下面按**当前代码真实缺口**写，不按旧勾选框原样复述。

## 总判断

练习闭环在「有资料 → 出蓝图 → 生成草稿 → 发布 → 开始作答」这条主路上已经能走通。真正粗糙的不是聊天壳，而是**学习产物的生命周期**：试卷出了以后怎么改、怎么留、怎么导出、怎么再做一遍；资料和 AI 文档怎么分版本；作答记录存在哪。

后端契约往往比界面完整一截。结果是：维护者能用 API 测通，学习者在界面上会碰到「没有入口 / 入口重复 / 对象越堆越多却删不掉」。

## 1. 组卷：能出卷，管不好卷

### 功能完成度

| 缺口 | 现状 | 对照 |
| --- | --- | --- |
| 题目手改 | 后端有草稿题替换、`question_order`、整卷 `PUT`。界面只有「改这题」一句话生成提案，不能改题干、选项、分值、顺序，也不能删一题。 | spec 35、36；Issue 09 注释「前端草稿编辑器尚未接入」仍成立 |
| 蓝图结构编辑 | 确认前只能改已有行的题量和每题分值。不能改难度、不能增删题型行、不能改时长。 | 组卷蓝图应能确认题型、题量、考纲、难度和分值 |
| 对象删除 | 后端可删蓝图、草稿、草稿题、试卷。前端 `deleteBlueprint` 已封装但无按钮；草稿/试卷没有删除入口。默认蓝图会留下多份同名卡。 | spec 53 删除要看到影响范围 |
| 错点回流不可见 | 解析蓝图时会把最近一次作答的错点塞进模型提示，且「仅当用户说复习/再出一套才纳入」。用户看不到这些考点从哪来，也无法确认这次有没有用上。 | Issue 24 用户故事：新蓝图考点里出现上次答错点，不想要就删 |
| 修改预览 | `/改卷` 能出提案，右侧 diff 用 `stringifyChange` 把结构化题目压成截断文本/JSON。 | 规范要求修改预览可理解，不要内部结构 |

### 交互

- 「新建蓝图」和空 `/组卷` 都会再产一份默认练习卷。科目里很快出现多张「……练习卷」，选中框只能重命名，不能清理。
- 组卷三步（确认蓝图 → 开始组题 → 发布）对自然语言入口是必要的；但对「新建蓝图」默认套卷来说偏重。用户已经点了默认题型，仍要再确认一次才组题。
- 组卷区输入框在没有蓝图时，超过 4 字的普通句子会**悄悄当成组卷要求**（`app.js` 里 `content.length > 4` 则 `parseBlueprint`）。这和「先说目标」一致，但和学习区普通聊天抢入口，也没有确认。

### 冗杂

- 生成路径是「一次整卷 bundle + 缺题再逐题补」。对用户仍表现为逐题状态，这是好事；对编排层则是两套提示和两套校验。Issue 09 的增量组卷语义还在，不要再加第三条生成管线。
- 废弃的章节速成产物接口、旧 `learning_mode` 仍在契约里。组卷主路径不应再依赖它们。

**建议：** 先做「对象可删 + 默认蓝图不堆卡」，再做「草稿手改题干/顺序」，蓝图增删题型行可以后做。错点回流至少要在考点行标明来源，不要只藏在提示词里。

## 2. 作答：能答题，留不住记录

### 功能完成度

| 缺口 | 现状 | 对照 |
| --- | --- | --- |
| 作答列表 | 契约**没有**列出某试卷全部作答的接口。前端把 attempt id 记在 `localStorage`（`lla.attempts`）。清站点数据、换浏览器、或 `start-attempt` 新开一份后，旧答卷在界面上消失，虽然还在科目数据里。 | spec 44–48、10「重新打开后恢复」 |
| 继续 vs 再做一套 | 「开始练习 / 开始考试」每次都 `createAttempt`。有进行中的作答时不会问「继续上次还是新开」。 | 暂停/恢复已做；缺的是作答对象本身的选择 |
| 考试时长 | 蓝图可带 `duration_minutes`，组卷页会显示「N 分钟」。作答计时是**经过时间**，到点不结束、也不倒计时。 | 不是必须倒计时，但现在两套时间互不相关，学习者会以为限时已生效 |
| 建议分数 | 练习模式创建作答时写死 `show_suggested_score: true`。没有开关。 | spec 48、主观题反馈「分数可选」 |
| 导出/打印 | 后端有统一渲染文档、题目版/答案版导出。前端没有打印、下载入口（`printer` / `download` 图标未用）。组卷主操作是「去作答」，标题栏也没有导出。 | spec 49–50；Issue 14 注释「前端打印视图尚未接入」仍成立 |
| 试卷版本 | 撤销/重做按钮在有历史时出现。没有版本列表、没有「恢复到版本 N」。 | spec 38 |

### 交互

- 作答页选试卷后只有「开始练习 / 开始考试」，看不出这份卷以前做过几次、上次做到哪。
- 考试模式完成前隐藏解析，这条门禁是对的。完成后揭晓依赖 `review`；练习主观题仍要再点「本题反馈」。对学习者合理，但「提交批改」和「本题反馈」的差别没有短说明（规范允许短状态，不要长教程；可用 tooltip）。
- 选区「问 AI」已接。Issue 12 还要求图片整张选区；当前选区来自 `window.getSelection()` 文本，图片题没有单独入口。

### 冗杂

- `POST /complete` + `POST /grade` 与旧 `POST /submit` 并存。前端走 complete/grade。不要再暴露第三条「提交」。
- 作答纸和组卷作者视图都在画题目，这是必要分工（考试不能泄漏）。不要把 Attempt.paper 和 Exam.document 合成一个组件以免漏答案，但说明块已经抽到 `solution.js`，应继续共用，避免再写第三套题目渲染。

**建议：** 产品上先补「这份试卷的作答记录」（哪怕第一版只列本机记住的 attempt + 状态），并让「开始练习」在已有进行中作答时默认继续。导出/打印是完整产品的硬缺口，应单独成票。限时倒计时不要和经过时间混在一个按钮上，要么做明确的考试倒计时，要么蓝图时长只当建议。

## 3. 资料与 AI 文档：上传强，整理弱

### 功能完成度

| 缺口 | 现状 | 对照 |
| --- | --- | --- |
| 资料版本切换 | 详情能写「共 N 个版本，当前 vK」，不能切回旧版本。`listSourceVersions` 有调用，没有恢复操作。 | spec 8、52 |
| AI 文档版本 | API 有 versions / restore。界面没有版本列表，也没有恢复。标题栏「生成文档」会再开一份新文档，而不是改当前这份。 | Issue 20；规范：用户上传只读，AI 文档才可改 |
| AI 文档修改 | `/改文档` 和提案应用/放弃已有。diff 对文档是内容块渲染，比试卷 JSON 预览好。仍不能从右侧直接说「改这一节」而不走斜杠命令。 | Issue 20「右侧显示差异」基本满足 |
| 章节速成提纲 | 后端仍能经废弃接口写出 `crash-course-outline` 学习产物。前端没有产物列表。ADR-0004 要求速成只是聊天风格，保存走 AI 文档。 | 旧产物类型是冗杂，不要接新 UI 去展示它 |
| 观测与评估 | `/api/evaluation-suites`、编排运行已在后端。前端没有入口。导航只有一个忙碌数字。 | Issue 15；维护者故事 55–56。学习者可以暂缓 |

### 交互

- ~~有用户资料时依据默认仍是「常识」。~~ **已定：有可用资料时默认「补充」，没有资料时默认「常识」；用户仍可改成「严格」。** 不要再按 Issue 04 做成默认严格。
- 会话资料图钉在学习区抽屉里，任务区靠 `@` 提及。两套范围（会话固定资料 vs 单条提及）对熟练用户有用，对新用户是隐式的。空状态没有「这份对话用哪些资料」。
- 临时附件和资料库是两回事（领域上正确）。附件只跟下一条消息。界面上回形针和资料抽屉并排，容易以为附件会进资料库。

**建议：** 默认依据已定为「有资料 → 补充，无资料 → 常识」。剩下的是 AI 文档版本恢复，以及「生成文档 vs 修改当前文档」分清主操作。评估界面不要进四个工作区。

## 4. 学习对话：风格在，产品承诺未收口

### 功能完成度

- 三种风格已是提示词，不是状态机，符合 ADR-0004。
- 「追问引导」仍可能被模型直接答完；这是模型遵守问题，不是再做阶段门禁。不要用按钮层级补。
- 明确「整理成笔记」走 `/文档`。聊天里没有「保存为文档」的隐式入口，这是对的。缺的是：章节速成聊完后，用户不容易发现要到资料区或打 `/文档` 才能留下提纲。

### 交互

- 学习区顶栏已经有风格、资料、模型；导航右侧又有模型。任务区聊天头也有会话切换和风格。模型入口重复（导航 + 对话头）。规范：任务标题栏一个主操作 + 最多三个图标；学习区右侧本来就该是对话工具，导航上的模型芯片可以只保留「未配置」警告。
- 斜杠命令菜单有方向键；科目/风格/依据/模型菜单只有点击。Issue 22 的键盘项仍空。
- 引用芯片最多 3 条，过宽问题 25 已缩短文案，检索是否对准问题仍取决于召回，不是界面能单独修完。

## 5. 应用壳与全局

- 四个工作区布局符合 ADR-0006，不要改回「四区都是左聊天」。
- 忙碌指示是导航上的数字，点不进去。失败操作靠 toast。对组卷这种长时间任务，数字不够，草稿 tab 的逐题状态才是正反馈（已有）。
- 删除科目用应用内确认；会话/资料也已改掉原生 `confirm`。蓝图/草稿/试卷仍删不了，所以「影响范围」在组卷对象上还是空的。
- 移动端隐藏 `.chip-label` 后，风格和模型只剩图标。可接受，但 tooltip 必须在触摸环境仍能被理解（长按/title 不够）。Issue 22 移动项仍开放。
- Favicon、空名称科目等 25 已修。

## 冗杂设计（单独收一处，避免各模块里重复）

这些不是「缺功能」，是**不要继续加厚**的地方：

1. **组卷生成双轨**：整卷 bundle + 逐题补齐。保留增量 UI，不要再加「一次生成但不显示槽位」的第三种用户路径。
2. **完成作答 / 提交批改 / 旧 submit**：前端只用前两个。
3. **对话风格 vs 废弃章节速成产物 / 废弃 `/chat/crash-course`**：新功能只走 `chat_style` + `/文档`。
4. **`learning_mode` 兼容字段**：不要在前端重新读它。
5. **学习产物 `crash-course-outline` vs AI 文档**：只保留 AI 文档作为可编辑产物。
6. **作答 id 只存在浏览器里**：和科目空间持久化原则冲突，补列表时应走服务端，而不是再做一套本地索引。
7. **组卷区把普通输入当成 `/组卷`**：与学习区聊天抢语义，属于隐式命令，建议取消或变成明确确认。
8. **默认蓝图工厂**：入口可以留，但必须能删、能认出「默认套卷」，否则会变成卡片垃圾场。
9. **题目说明渲染**：继续只用 `solution.js`，组卷作者视图和作答复盘不要再分叉。
10. **观测/评估**：保持后端能力即可，不要塞进四个学习工作区。

## 建议拆票顺序

按「闭环能不能用完」而不是按技术层：

1. **作答记录与试卷对象生命周期**（新票）  
   列出一份试卷的作答；进行中默认继续；蓝图/草稿/试卷可删（带影响范围）。没有这个，组卷越好，垃圾对象越多。

2. **试卷导出与打印**（收口 Issue 14 前端）  
   题目版 / 答案版明确选择。这是 spec 对「试卷」定义的一部分，不是锦上添花。

3. **资料依据默认值**（已定，不必再开票）  
   有可用资料 → 补充；没有资料 → 常识。用户可改成严格。不要做成默认严格。

4. **草稿手改**（收口 Issue 09 前端编辑器）  
   至少：改题干/选项/分值、调序、删题。AI「改这题」留下作为加速，不代替手改。

5. **AI 文档版本与「改当前」**（收口 Issue 20 剩余）  
   标题栏主操作在已有文档时不应总是新建。

6. **Issue 22 剩余 polish**  
   键盘菜单、移动端图标可理解性、修改预览不要 JSON。可与 4 一起做预览，不要单独做成大重构。

7. **考试时长策略**（需产品决定）  
   要么蓝图时长变成作答倒计时，要么界面改成「建议用时」，避免和经过时间抢语义。

8. **观测界面**（Issue 15）  
   维护者工具，不要插在四个工作区里。可 `wontfix` 到有明确维护入口再做。

Issue 23 的界面收口已基本在代码里，不要重开。Issue 24 的考点可见已做；未做的是「错点出现在新蓝图考点里且用户能认出来」，可并进组卷小票，不要重做芯片。

- 若拆票：一组生命周期（删/列表/继续），一组导出，一组手改。依据默认已定为「有资料补充 / 无资料常识」。
- 2026-08-20：产品决定有可用资料时默认走补充通用知识，而不是资料严格模式。前端已按科目记住用户改过的依据。
- 2026-08-20：竞争力方向已拆票——27（作答记录与对象生命周期，对应本票拆票 1）、28（导出打印，对应拆票 2）、29（检索质量与引用跳转）、30（错题视图与再练一套，并入了「错点回流可见」）、31（聊天流式输出）、32（一键启动）、33（科目导出导入）。草稿手改（拆票 4）、AI 文档版本（拆票 5）、Issue 22 polish 与考试时长策略仍待开票。建议实施顺序：27 → 28 → 29 → 30 → 31 → 32/33。
