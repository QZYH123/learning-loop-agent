# 06 — 苏格拉底对话风格

**What to build:** 在普通资料问答上增加苏格拉底对话风格。它只通过提示模板或类似 skill 的工具指令改变 AI 的交流方式，不建立固定教学流程，也不限制用户下一条消息。

**Blocked by:** 04 — 资料检索和来源引用

**Status:** ready-for-agent

## Contract

- [ ] 使用 `chat_style: default | socratic | crash-course` 表示对话风格
- [ ] 允许会话默认风格和单条消息临时覆盖，切换风格不清空消息或资料范围
- [ ] 废弃前端依赖的 `SocraticState`、`hint_level`、`answer_revealed` 和阶段型消息 `intent`
- [ ] 普通用户消息始终可以发送，不因上一轮处于某个教学阶段返回冲突

## Backend

- [ ] 苏格拉底风格向同一聊天调用附加稳定的风格指令，优先提问、要求尝试、检查理由和纠正常见误解
- [ ] 模型根据当前对话自行决定何时提示、解释、要求复述或给出变式问题
- [ ] 用户可以直接说“给点提示”“直接解释”“考考我”，不需要专用 API 动作
- [ ] 风格指令继续服从资料严格、补充通用知识和常识模式的依据边界
- [ ] 普通回答、来源、模型快照和完整会话照常保存
- [ ] 不解析模型回答来驱动应用级教学状态机

## Frontend

- [ ] 对话输入区提供紧凑的 `普通 / 苏格拉底 / 章节速成` 风格选择器
- [ ] 不显示“提示 1/2/3”“启发中”“等待复述”“自测阶段”等状态
- [ ] 不显示强制的开始、尝试、提示、复述和自测按钮序列
- [ ] 用户用自然语言要求提示、解释、复述检查或变式题
- [ ] 风格切换只影响后续回复，历史消息不改写

## Verification

- [ ] 测试风格指令被应用且资料依据边界不变
- [ ] 测试任意普通消息在任意上一轮内容后都可发送
- [ ] 测试切换风格保留消息、资料范围和当前模型
- [ ] 浏览器检查界面不存在提示层级、教学阶段和强制动作栏

## Comments

- 原实现使用 `ChatMessageInput.intent`、`SocraticState.stage` 和提示层级推进流程，与当前产品路线冲突；这些字段只能作为迁移期兼容数据，不能继续指导前端交互。
