# 17 — 多学习会话和显式资料上下文

**What to build:** 一个科目空间支持多个独立学习会话。每个会话保存自己的消息和固定资料版本，新增资料或新版本不会自动进入已有会话。

**Blocked by:** 16 — API 契约和工作流状态基线；02 — 基础问答和模型切换；03 — 基础资料库；04 — 资料检索和来源引用

**Status:** ready-for-agent

## Contract

- [ ] 只实现 Issue 16 已确认的会话、上下文快照和附件契约
- [ ] 后端实现前先补齐对应契约测试

## Backend

- [ ] 为科目保存多个会话和当前会话标识
- [ ] 支持创建、读取、切换、重命名和删除会话
- [ ] 第一条消息后生成默认会话标题，用户可覆盖
- [ ] 删除会话不删除项目资料或 AI 生成的资料文档
- [ ] 创建会话时只绑定用户显式选择的资料版本，普通新会话默认不绑定资料
- [ ] 会话资料版本不会自动跟随资料库更新，只能显式加入、移除或更新
- [ ] 从外部长期加入的资料同时进入当前项目资料库和当前会话
- [ ] `@资料` 优先检索被点名的会话资料，但不排除其他会话资料
- [ ] 只有显式“仅使用指定资料”时才限制检索范围
- [ ] 临时附件只属于当前消息，不进入项目资料库或会话资料范围
- [ ] 每条消息保存实际资料版本、模型、依据模式和附件快照
- [ ] 检索只向模型注入有限的相关片段，不发送全部资料全文
- [ ] 聊天前端按契约渲染内容块数组，不把对象隐式转换为字符串
- [ ] 消息请求使用契约允许的资料引用字段，不发送非法 `document_kind`

## Frontend

- [ ] 提供会话列表、新建、搜索、重命名和删除操作
- [ ] 创建会话时提供当前项目资料选择
- [ ] 会话资料通过下拉列表管理，不显示无意义的资料数量卡片
- [ ] `@` 菜单仅列出当前会话资料，并标记本轮重点引用
- [ ] 临时附件显示缩略图、文件名、大小、移除和失败状态
- [ ] 无 Vision 模型时禁用图片发送并提示切换模型
- [ ] 临时附件请求和会话资料请求分别符合对应契约

## Verification

- [ ] 自动化测试覆盖会话隔离、资料版本固定、显式更新、`@` 优先检索和附件生命周期
- [ ] 不同会话之间不共享消息历史或默认资料范围
- [ ] 历史消息可以复现当时的资料依据和模型快照
