# 21 — 作答完成标记和批改解耦

**What to build:** 将用户主动标记“完成作答”和“提交批改”拆成两个独立操作。完成标记不自动触发批改，批改完成也不自动替用户标记完成。

**Blocked by:** 16 — API 契约和工作流状态基线；10 — 客观题答题；11 — 主观题批改反馈

**Status:** ready-for-agent

## Contract

- [ ] 复用 Issue 16 定义的作答完成状态、批改状态和恢复接口
- [ ] 明确答案可编辑性、反馈可见性和批改过期语义

## Backend

- [ ] 分别保存用户完成状态和批改状态
- [ ] 修复前端直接把普通 state 对象当作 Store 调用的问题
- [ ] 用户可以主动标记作答完成，不触发批改
- [ ] 完成后答案只读，并可通过“继续作答”撤销完成标记
- [ ] 用户可以独立提交批改
- [ ] 存在未答题时提示用户，但允许继续标记完成
- [ ] 修改已经批改的答案后，将受影响反馈标记为过期或需要重新批改
- [ ] 批改失败可以重试，不改变用户完成标记

## Frontend

- [ ] 作答工作区左侧始终是 AI 对话，已发布试卷列表放在右侧局部导航或抽屉
- [ ] 作答页提供紧凑的“完成作答”操作
- [ ] 独立提供“提交批改”操作
- [ ] 列表分别显示作答完成状态和批改状态
- [ ] 完成后的作答提供“继续作答”入口
- [ ] 正式考试和练习模式遵循各自的答案、解析和反馈可见性规则
- [ ] 题目选区可以发送到左侧对话；考试模式下不得通过问答泄漏隐藏答案

## Verification

- [ ] 测试完成不批改、批改不完成、恢复作答和反馈过期
- [ ] 测试未答题提醒、批改失败重试和历史状态恢复

## Comments

- `完成作答`、`提交批改`和`继续作答`属于右侧标题栏的上下文操作，不应占用左侧 AI 对话栏。
